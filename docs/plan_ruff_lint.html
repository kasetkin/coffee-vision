The order of work for ticket OPS-4. Four strands: the [tool.ruff] configuration, the 62 existing findings, the check.sh step and the pre-commit hook. The configuration comes first, because it defines what ruff check means. The fixes follow it, so each gate starts out green (D3). 1. Phase order and why

The configuration lands first. It changes no code, and it makes a bare ruff check mean the D1 rule set on D4's paths, which every later phase runs. The fixes come next, before either gate, so neither gate is red on arrival. They are grouped by how each kind is proven harmless. Statement splits leave the AST identical, so a script can prove them. Removals are short, and the diff is read. Renames are checked by Ruff itself: a missed occurrence of the old name becomes an F821 undefined name. check.sh comes before the hook because it is the gate that already blocks pushes and deploys. The hook is the part with new code and tests.

3. P1 — the configuration

StatusOpen not started
Blocked byNone

Ruff is configured in the root pyproject.toml, after the [tool.uv] tables, with each choice commented, as the file comments its other entries:

[tool.ruff]
# OPS-4. The target version comes from requires-python (3.12). No line length: no selected rule reads it,
# and the formatter is its own ticket (D2).
# third_party/ is the vendored EfficientViT-SAM (ML-2), kept diffable against upstream (D4).
extend-exclude = ["third_party"]
# The exclusion holds for paths named explicitly too: the pre-commit hook and the editor pass them.
force-exclude = true

[tool.ruff.lint]
# The pyflakes/pycodestyle core (D1), written out so that a Ruff upgrade adds no rule family (R2). New stable
# rules inside these prefixes come with an upgrade (D8); the version is pinned by uv.lock only.
select = ["E4", "E7", "E9", "F"]

extend-exclude, not exclude, keeps Ruff's built-in exclusions (.venv, .git, caches). target-version is not set: requires-python = "==3.12.*" already sets it, and a second copy could drift from the first. The test guards what a comment cannot: that nothing shadows the root table (R5), and that the paths are the ones D4 named.

  1. Add the two tables above to pyproject.toml. No uv lock is needed: tool tables do not enter the lock.
  2. tests/test_ruff_config.py: (1) no tracked ruff.toml or .ruff.toml, and no tracked pyproject.toml other than the root one with a [tool.ruff] table (read with tomllib). (2) python -m ruff check --show-files lists webapp/app.py and tests/test_ruff_config.py, and no path under third_party/.

6. P4 — the check.sh step

StatusOpen not started
Blocked byP3

The step is run ruff python -m ruff check --output-format concise, placed after ticket_check with the other static checks. python -m ruff runs the Ruff of the interpreter that runs the other steps, the locked 0.16.10. concise prints one line per finding, so the 40-line tail run prints on failure holds about 40 findings instead of about 6 code frames. Exit 2 (a config error) fails the step like exit 1. Its cost is under a second, so both tiers run it.

The step lints the working tree, not only the commit its caller vouches for (D9): an untracked .py with a finding fails the push or the deploy. Gitignored files are allowed too, but Ruff's default respect-gitignore stays on: turned off, it adds 18 findings in the Claude skill scripts synced into the gitignored .private_claude/, which are not the project's code.

  1. Add the step. In the header comment, add ruff check (the lint rules in pyproject.toml's [tool.ruff], <1 s) to the list of steps.

7. P5 — the pre-commit hook

StatusOpen not started
Blocked byP4

The hook lints the commit, not the disk (R6), so it feeds Ruff each staged blob. The logic lives in a Python module with unit tests, as leak_check and ticket_check do. The hook stays a thin runner, since a bash loop cannot be tested by the suite. coffeecv/ruff_staged.py:

  • The files: leak_check.published_files(root, staged=True) (added, copied, modified, renamed), filtered to the extensions ruff check includes (.py, .pyi, .ipynb). Symlink and submodule entries are skipped by their index mode (git ls-files -s: 120000, 160000), as leak_check skips them on disk.
  • Per file: git show :<path> piped into [sys.executable, "-m", "ruff", "check", "--output-format", "concise", "--stdin-filename", path, "-"] from the repo root. The config, with force-exclude, resolves from path, so a staged third_party/ file passes. Each file costs about 85 ms, most of it the Python start of python -m ruff, so a 30-file commit adds about 2.5 s. The module's own start adds about 1.7 s, as leak_check's does: importing leak_check pulls in torch through coffeecv.config. Measured 2026-10-07.
  • It prints the findings and ends on one line, like leak_check: ruff_staged: N staged Python files clean or ruff_staged: K finding(s) in N staged Python files. It exits 1 on any nonzero Ruff exit. A missing Ruff (No module named ruff) fails loudly with "run uv sync --locked", and never skips.

The hook runs both checks, so one commit reports every failure, as check.sh does:

cd "$root" || exit 1
rc=0
python -m coffeecv.leak_check --staged || rc=1
python -m coffeecv.ruff_staged || rc=1
exit $rc
  1. coffeecv/ruff_staged.py as above, with a module docstring in leak_check's style.
  2. tests/test_ruff_staged.py, on a temp repo like tests/test_leak_check.py's fixture, holding a pyproject.toml with the P1 tables. Cases: a staged unused import is reported. A file clean in the index but dirty on disk passes, and the reverse is reported. A staged file under third_party/ passes. A staged deletion and a staged .md are not linted. With nothing staged, the module exits 0.
  3. .githooks/pre-commit as above. Its header comment names both checks with their cost (about 1.7 s each to start, plus about 85 ms per staged Python file for Ruff) and says Ruff reads the index while leak_check reads the disk, until Q1's follow-up.
  4. README.md line 26: "runs the leak check alone" becomes the leak check and Ruff on the staged files.
  5. The VM: check git -C ~/coffee-vision config core.hooksPath and ~/coffee-vision-venv/bin/python -m ruff --version. If the hooks are wired there, its next commit runs this hook, and Ruff must be in that venv (the dev group is synced by default). Write the result in the Activity entry.
  6. Checks, by hand in this repo: stage an unused import and the commit is refused. Stage a clean version, then add the import on disk only, and the commit goes through. A file with a leak and a lint finding reports both. scripts/check.sh passes.
