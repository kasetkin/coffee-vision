2.2 The shared interface

One function sits behind both the training crop stage and infer.patches_for_photo, per the train/inference parity rule. Sketch:

@dataclass(frozen=True)
class SegParams:                 # all from RunConfig, recorded in every checkpoint
    weights: str                 # repo-relative path
    weights_sha256: str
    prompt: str                  # "box" (D5 a) | "grid3" (D5 b fallback)
    mask_select: str             # fixed in P0 (§3), e.g. "single" | "best_iou"
    keep_frac: float = 0.95      # D4: cut (1-keep)/4 per side
    fill_rgb: tuple = (124, 116, 104)   # D3: ImageNet mean, rounded to uint8
    min_area_frac: float = 0.0   # D18: set in P2

@dataclass
class BeanCrop:
    rgb: np.ndarray              # filled crop, or the whole original photo on fallback
    mask: np.ndarray | None      # bool, aligned with rgb; None = fallback (accept every patch)
    info: dict                   # mask_area_frac, bean_frac_in_crop, retained_frac,
                                 # fallback, box, mask_sha256, timing_ms

class BeanSegmenter:
    def __init__(self, p: SegParams): ...           # loads L0 once
    def predict_mask(self, rgb) -> np.ndarray: ...  # bool HxW at full resolution

def mask_and_crop(rgb, mask, p: SegParams) -> BeanCrop: ...   # pure numpy, unit-testable
def segment_and_crop(rgb, seg: BeanSegmenter, p) -> BeanCrop: ...
  • predict_mask upsamples the logits to full resolution and removes SAM's bottom/right padding first, then thresholds at 0. That follows SAM's own postprocess. The pad-then-crop step is where an off-by-pad misalignment would come from, so it gets its own test.
  • The fill does not normalize to exactly 0 once rounded to uint8. Channel values come out at +0.006, −0.005 and +0.008. That is negligible, but the ticket's wording is corrected in the ticket update at P3.
  • crop_method is a new RunConfig field: "tray_heuristic" | "segment". A checkpoint without it restores as "tray_heuristic", so allrigs_dino3b16_s123 keeps today's path with no change. CLI flags for the new fields inherit from the checkpoint and never reset to zero.

4.3 Overlays, prompt and defects

  1. seg_overlay.py: an overview at ≤1568 px on the long side, with a 2 px magenta outline (it contrasts with both green and roasted beans) and the dashed crop box; plus 6 full-resolution boundary tiles of 768 px, labelled T1–T6 on the overview. Four tiles are evenly spaced along the contour and two sit at the lowest-confidence boundary points (logit nearest 0). Images are PNG, encoded from pixel arrays, so no EXIF, GPS or C2PA can pass through. Done 2026-09-30. Deviation: all six tiles are evenly spaced along the contour. Base masks are stored bits and planted defects have no logits, so logit-placed tiles would differ between the masks judged and the masks the judge is checked on. The frame edge is outlined where the mask reaches it (a frame-filling mask shows a magenta border), and the message states the mask's area share.
  2. judge_prompt.md holds the glossary definitions, then the D13 rule verbatim, then the output schema: {"verdict": "accept|decline", "failed_rules": [1-4], "reason": str, "points": [{"where": "overview|T1..T6", "x": 0-1, "y": 0-1, "label": "include|exclude"}]}, at most 6 points. A verdict that fails to parse is retried once, then stored as unjudged. It never defaults to accept. Done 2026-09-30. Adds three lines on how the owner applied the rule in D25 (small holes, a boundary on the inner rim, frame-filling masks), outside the verbatim rule; owner to confirm.
  3. seg_defects.py defect types: shift, erode, dilate (grows onto tray/rim), drop_corner, add_band (joins a strip of tray outside the pile). Magnitudes are drawn so each type straddles the D14 boundary: crop IoU ≤0.90 vs the clean crop, or added non-bean area ≥5% of the bean region. "Snaps to single beans" and "outlines a non-coffee pile" can't be planted realistically. The owner's blind audit (P2) covers those. Done 2026-09-30. Magnitudes are searched on a ladder at 1024 px and planted at full resolution; dilate and add_band can't be planted on frame-filling bases (11 of 25 dev and 12 of 25 held-out bases have room). Pilot set: labels/ml2/defects/pilot.csv, regenerates bit-identically.
  4. seg_judge.py: --backend cli runs claude -p --model <id> --output-format json with the overlay paths and only the Read tool allowed; --backend api sends base64 images, with --batch for Message Batches. Each row records the key, model ID, prompt sha, overlay sha, backend, tokens, cost, round and timestamp. An existing (key, model, prompt) is skipped unless --rejudge is passed. Items are sent one per call, so the judge never sees the base mask behind a defect. Done 2026-09-30; tested with a fake backend (tests/test_seg_judge_io.py), no judge called yet. The skip key also holds the backend and the trial, so the pilot can run both backends and the final check can judge each clean base twice. The cli backend runs from a fresh temporary directory (no CLAUDE.md, no project settings). The api backend needs the anthropic package, which isn't in the lock yet, and an API key.

6. P3 — integrate

  1. segment_beans.py per §2.2, and RunConfig fields: crop_method, seg_weights, seg_weights_sha256, seg_prompt, seg_mask_select, seg_keep_frac, seg_min_area_frac, patch_min_bean_share (0.80), patch_max_attempts_factor (20). All of them are written to the checkpoint JSON and restored by config_for_checkpoint.
  2. geometry.sample_masked_bean_unit_boxes: draw candidates from the same bean-unit distribution; score each box's bean share in O(1) from an integral image; accept a box if share ≥ threshold; stop at factor × n attempts; top up with the best rejected boxes, highest share first; return n_below. With mask=None it accepts everything (D18). RNG consumption changes, so boxes differ from today's even on all-bean crops. That is expected, because the pools regenerate anyway.
  3. Training side: coffeecv/segcrop_session.py (segcrop@<session> stage) writes <stem>__cropped.jpg (filled, q95 as today), <stem>__beanmask.png (1-bit, crop-aligned, absent on fallback) and a per-class segcrop_report.json. merge_rig.py copies the mask sibling (F3). MultiPhotoPatchDataset._extract_photo loads the mask when crop_method == "segment" and calls the D17 sampler.

Add them to webapp/app.py's request-log fields. /preview uses the same segmenter; note that it doubles the segmentation cost per upload.

The JPEG q95 re-encode of training pools is an existing train/serve difference; this plan doesn't widen it.

  3. Stage seg_finetune on the VM through dvc repro, seeds 42/123/7, with the recipe below. Select each seed's checkpoint on seg_val only.
  4. seg_predict@ft → judge → seg_eval@ft. Judge all three seeds if the pilot's cost allows; otherwise judge the seg_val-selected seed and report the seg_val spread.

11. Compute and cost

  • Segmentation passes: ~940 pool photos per segcrop run, plus ~1 000 list photos for seg_predict. The per-photo cost comes from P0; at a few seconds per photo, each is well under an hour on the VM.
  • Embedding cache: ~2 MB per view per photo in fp16 → ~1.3 GB per view for ~650 photos. Hence push: false.
  • Decoder fine-tune: the decoder is ~4M parameters, and cached embeddings mean no encoder pass. Expect minutes per epoch on CPU. The encoder+decoder retry is the expensive case and gets its own estimate first.
  • Head refits: 6 runs in P4 and 3 in P6, the same cost as the allrigs_dino3b16 fits.
  • Judge: up to ~4 700 items in total (§4.4), all of them full-photo masks; the pilot turns that into money or plan usage.
