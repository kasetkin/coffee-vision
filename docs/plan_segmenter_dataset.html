Implementation plan: segmenter dataset from scratch

The order of work for ticket ML-5. Three strands: the data (commit, rename), the OOD guard's new ADR, and the segmenter-then-classifier rebuild. The data comes first because everything reads it; the ADR can run beside the dataset work. The first step that changes a number is P6, the fine-tune.

Built from a read of the code at 9619ec9, not from the ticket alone. Three things the ticket does not cover turned up. They are folded in below, and the ones that need a decision are Q1–Q7 (§2).

  1. ML-2's lists pin dataset/ood_positives/... paths and are append-only. seg_lists build refuses to move an entry, so after the rename it can no longer run on them. The new dataset gets its own file under labels/ml5/; ML-2's file stays as history (P2, P4).
  2. The seg_* DVC stages read ML-2's lists. seg_embed_cache, seg_finetune, seg_predict and seg_eval are repointed at the new file in P4–P6; the ML-2-only stages (seg_predict_ml3_new, the base-mask lists) are retired.
  3. The guard code takes positives by path. fit_ood_probe --positives and ood_eval --positives are documented with dataset/ood_positives; they follow the new ADR in P3, not the rename.

1. Phase order and why

P1 and P2 move and rename data without changing any model output. P3 is a decision written down. P4 and P5 build the dataset and its labels; nothing is trained until P6. P7 changes what the classifier sees.

2. Questions for the owner

Each comes from the code or the data, not from the ticket's decisions. Each has a recommendation, which this plan assumes until it is answered.

IDQuestionRecommendationBlocks
Q1How are the random main-dataset photos drawn? The 1,248 photos are uneven across folders (20 to 180 each) and cameras. Open As many as segmenter_positives holds (128), stratified by folder in proportion to its size, at a new seed, skipping any photo already in segmenter_positives. Proportional keeps the classifier's own mix; skipping copies keeps the count honest.P4
Q2The split ratios, and what "cal" does. Open 70/15/15 train/cal/test within each source, at a new seg_split_seed. Cal only chooses the fine-tune checkpoint (as ML-2's seg_val). Byte-identical files and shots within 120 s of each other form one group and move together.P4
Q3Do all 142 OOD negatives join, holdout included, and all 12 internet positives? Their dev/holdout split existed for the guard. Open Yes, all, re-split by Q2 within each (batch, tag). The guard holdout's role ends with ADR 0005; Q5 says what measures the guard instead.P4, P3
Q4How is the segmenter's test split scored? Open As ML-2 did: the judge's verdict on each test mask under the D13 rule (pass rate), plus the share of test negatives whose mask is empty or tiny. Test masks are judged, never used to train.P5, P6
Q5How is OOD defined and measured in the new ADR? Open The guard stays a linear probe with a fixed 0.5 threshold, set by the owner, not calibrated. Fitted on classifier-train bean patches against the train-split negatives; measured, not gated, on the segmenter test split: negatives caught, and positives refused, reported separately for photos the classifier trained on and photos it did not.P3, P7
Q6Does the fine-tune recipe change? Open No: ML-2's decoder-only fine-tune (D7), seeds 42/123/7, so only the data differs.P6
Q7What does the classifier report show before a ship decision? Open ML-2 D24's printout against the shipped model: per seed, val and test patch macro-F1, the paired differences and per-class F1; plus the Q5 guard numbers. No numeric gate.P7
