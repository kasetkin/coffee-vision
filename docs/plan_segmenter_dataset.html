Implementation plan: segmenter dataset from scratch

The order of work for ticket ML-5. Four strands: the data (commit, rename), the two ADRs and the guard, the XL0 code and the review page, then two labelling and fine-tune passes followed by the classifier. Code that the owner's labelling sessions need comes before them; the first step that changes a number is P8, XL0-v1.

Built from a read of the code at 9619ec9 and a measurement on 2026-10-08, not from the ticket alone. Five things the ticket's first draft did not cover turned up; all are folded in below.

  1. ML-2's lists pin dataset/ood_positives/... paths and are append-only. seg_lists build refuses to move an entry, so it cannot run after the rename. The new dataset gets its own file under labels/ml5/; ML-2's file stays as history (P2, P5).

Hence pretrained L0 for pass-1 corrections and point prompts in the XL0 fine-tune (D15, D19), all through multi3 (D23). The probe that measured it becomes a committed check (P6).

1. Phase order and why

P1–P3 move data and write decisions down without changing a model output. P4–P6 build what the labelling sessions need; P5's dataset file is the first input to labels. P7–P10 are the two passes, each a labelling session and a fine-tune. P11 changes what the classifier sees.
