Implementation plan: segmenter dataset from scratch

The order of work for ticket ML-5. Four strands: the data (commit, rename), the two ADRs and the guard, the XL0 code and the review page, then two labelling and fine-tune passes followed by the classifier. Code that the owner's labelling sessions need comes before them; the first step that changes a number is P8, XL0-v1.

Built from a read of the code at 9619ec9 and a measurement on 2026-10-08, not from the ticket alone. Five things the ticket's first draft did not cover turned up; all are folded in below.

  1. ML-2's lists pin dataset/ood_positives/... paths and are append-only. seg_lists build refuses to move an entry, so it cannot run after the rename. The new dataset gets its own file under labels/ml5/; ML-2's file stays as history (P2, P5).
  2. The seg_* DVC stages read ML-2's lists; they are repointed in P8, and the ML-2-only stages (seg_predict_ml3_new, the base-mask lists) retired.
  3. The guard code takes positives by path and calibrates a threshold; P3 removes the calibration (D9).
  4. L0 is wired in. seg_finetune.py hard-codes the 512 frame (FRAME) and build_sam_l0; sam_loader already lists xl0 with its 1024 px input (P4).
  5. ft_s123 does not follow point prompts (ticket §2: 17–35% of accepted masks reproduced from their own points, 35–48% empty), through multi3 as well as single (re-measured on 253 masks, analysis/ml5_point_probe/). Hence pretrained L0 for pass-1 corrections and point prompts in the XL0 fine-tune (D15, D19), all through multi3 (D23). The probe that measured it becomes a committed check (P6).

1. Phase order and why

P1–P3 move data and write decisions down without changing a model output. P4–P6 build what the labelling sessions need; P5's dataset file is the first input to labels. P7–P10 are the two passes, each a labelling session and a fine-tune. P11 changes what the classifier sees.

8. P6 — Review page with points; the point probe

StatusOpen not started
Blocked byP4, P5
  1. review_masks: hold g + left-click adds an include point (green), r + left-click an exclude point (red); a plain click still opens the spot at full resolution. Undo the last point; redraw on demand.
  2. Labelling mode over the dataset file: round 1 shows the proposer's mask; a decline asks for points; the redraw model draws from the box plus all points so far; up to 3 rounds; still declined means dropped, reason logged. Proposer and redraw model are arguments (pass 1: ft_s123 and pretrained L0, D19); every redraw uses the multi3 output (D23), replacing seg_labels.CORRECTION_OUTPUT’s single. Negatives are never shown; their labels are empty.
  3. Each photo's embedding is computed once before the session for the redraw model, so a click reruns only the decoder.
  4. Blind paired mode for P10 (D22): two models' masks of one photo side by side, sides randomised and recorded, model names hidden until the session ends; a verdict per mask.
  5. Verdicts, points and masks stored as ML-2 D16 stored them: verdicts and points in git (labels/ml5/), masks DVC-tracked.
  6. The point probe as coffeecv/seg_point_probe.py: for a model and a set of accepted masks with their points, replay the points and simulate 3 corrective clicks, each at the distance-transform maximum of the largest error region; the decoder output is an argument (D23); print IoU ≥ 0.9 and empty shares per click. Built from analysis/ml5_point_probe/point_probe.py and reproduces its summary.txt.
  7. Checks: a smoke run of the page on 3 photos, points and the blind paired mode included; the probe's numbers match analysis/ml5_point_probe/summary.txt.

10. P8 — XL0-v1

StatusOpen not started

  2. Point prompts in training (D15): some batches add 1–3 points sampled from the error region of the box-only prediction, the box kept; the share is a param. Those batches train the multi3 output, as box-only batches do (D23). Checkpoint selection stays box-only.

  5. No test verdicts or test numbers here: XL0-v1's test predictions are stored and judged with XL0-v2's in P10 (D22).

Explicitly not in this change

  • Everything in the ticket's "Out of scope". Changes to the acceptance rule.
  • Minor points from the 2026-10-08 recipe check, left out on purpose: feeding the previous mask's logits back on a redraw (tested: not clearly better than plain pretrained L0); training the lowest-loss output as SAM does (ours trains the output serving keeps); a learning rate below 1e-4 (try 1e-5 first if XL0's validation curve is noisy); colour augmentation (cached embeddings allow flips only); IoU against reference masks on test (the owner's verdicts are pass/fail); encoder adapters (ML-2 D7's fallback).
