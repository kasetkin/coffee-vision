What happens between a decoded photo and a returned verdict

Traced from coffeecv/infer.py:classify_one, the function both the CLI and webapp/app.py's POST /classify call — same code path, so nothing shown here differs between the two. Upload handling, tempfile plumbing, and JSON shaping are left out; everything from the decoded RGB array to the ranked class list is included.

checkpoint: allrigs_dino3b16_seg_country_s123.pt backbone: DINOv3 ViT-B/16, frozen, + linear head 40 patches × 1 view = 40 forward passes as of 2026-10-06
On "votes": there is no ensemble of separate models or rigs in the shipped path — one frozen DINOv3 backbone and one linear head. What plays the role of voting is averaging: 40 patches cut from the photo, each scored once, softmax probabilities mean-averaged across patches into a single vector. The final class is its argmax. (The ResNet18 fallback, allrigs_cam_s123, also averages 8 dihedral views per patch first, because its card turns TTA on: 320 passes instead of 40.)

Three mechanisms worth reading in full

The rest of the pipeline is fairly linear; these three points are where a decision actually gets made.

1

Bean pitch — patch size measured in beans, per photo

coffeecv/infer.py · patches_for_photo()

Bean pitch is measured per photo by FFT, not assumed from a fixed zoom level — a user pointing a phone can't be expected to frame consistently. Each patch is 4–7 pitches on a side, so it holds the same number of beans at any zoom, exactly as in training. There is no scale refusal: the guard that used to refuse "too tight" frames could never fire (beans_across has a floor of 8.2 against thresholds of 4 and 7) and was deleted on 2026-09-03. beans_across is still logged on every request, so a future guard can be calibrated on real traffic (docs/scale_guard_plan.md). Since the segmenter model (ticket ML-2), the pitch is measured on the filled crop, and a patch with less than 80% bean region under the mask is redrawn; after 20 × 40 attempts the best rejected boxes top the photo up to 40 (D17). mask_area_frac, bean_frac_in_crop, retained_frac, seg_fallback and patches_below_share are logged per request.

pitch = estimate_bean_pitch(grayscale_like_training(rgb), **pitch_kwargs(cfg))

2

The "vote" — 40 patch probabilities averaged into one

coffeecv/infer.py · classify_one()

Each of the 40 patches goes through the frozen backbone and the head once. Their softmax vectors are mean-averaged into a single vector, and the label is its argmax. Whether each patch is first averaged over 8 dihedral views is a property of the model, read from its card: on for the ResNet18 fallback (+0.0235 macro-F1 there), off for DINOv3, where 8 views would cost about 46 s a photo and the gain is unmeasured.

Since the country model (ticket ML-3, allrigs_dino3b16_seg_country_s123, released 2026-10-06), the classes are countries: the ten keys of dataset/classes.txt's D15 lines (Brazil, CostaRica, ...), read through class_list.load_classes from the model's frozen .classes.txt. Several coffee folders train as one country. The request log's top1_class (webapp/app.py) therefore holds a country key from that release on, where earlier releases logged a folder id (006). A recalibration that joins logs across releases maps the old ids to countries through the D15 file. The ResNet18 fallback and the previous release keep their own folder-id lists, so a rollback shows folder classes again.

tta = inference_tta_for(checkpoint, cfg.model_name)   # card: inference_defaults.tta
probs, embeds = forward_with_embeddings(model, head, patches, tta=tta)
mean = probs.mean(axis=0)              # the final "vote"
ranked = sorted(zip(class_ids, mean), key=lambda t: -t[1])
3

Out-of-distribution guard — the linear probe

coffeecv/infer.py · probe_score(), classify_one()

Softmax confidence alone was found to be useless here (0.97 on a genuinely out-of-rig photo, indistinguishable from 0.997 on an in-distribution one), so the guard asks a different question: does each patch's embedding look like a bean patch? A logistic probe, fitted in this model's own 1536-d space on genuine photos against non-bean negatives, gives P(not beans) per patch; the mean over the 40 patches is the photo's score. It refuses above 0.5 (the owner's choice, kept for the segmenter model on 2026-10-03 and for the country model on 2026-10-06: on the holdout 2/29 genuine photos refused and 56/56 negatives caught; the calibrated threshold is 0.5957; the holdout was read before, so this is a regression check, not a fresh validation, analysis/ml3/README.md) and warns between the 20%-false-refusal point and 0.5. A checkpoint without a probe file falls back to the older centroid distance, refusing above 1.4. docs/ood_guard_eval.md has the ResNet18 guard's record; docs/dinov3_integration_plan.md §9.3 has this one's.

def probe_score(embeddings, probe):
    z = ((embeddings - mu) / sd) @ w[:-1] + w[-1]   # per patch
    return mean(sigmoid(z))                      # P(not beans), per photo
