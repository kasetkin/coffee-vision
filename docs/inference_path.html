What happens between a decoded photo and a returned verdict

Traced from coffeecv/infer.py:classify_one, the function both the CLI and webapp/app.py's POST /classify call — same code path, so nothing shown here differs between the two. Upload handling, tempfile plumbing, and JSON shaping are left out; everything from the decoded RGB array to the ranked class list is included.

checkpoint: allrigs_mixstyle05_e100p20_s17.pt backbone: resnet18 40 patches × 8 TTA views = 320 forward passes
On "votes": there is no ensemble of separate models or rigs in the shipped path — one ResNet18, one checkpoint. What plays the role of voting is averaging: 40 patches cut from the photo, each scored under 8 dihedral views (rotations × flips), softmax-averaged per patch and then mean-averaged across patches into a single probability vector. The final class is just the argmax of that average — the "election" is 320 probability estimates converging on one mean, not distinct voters being tallied.

Three mechanisms worth reading in full

The rest of the pipeline is fairly linear; these three points are where a decision actually gets made.

1

Scale guard — can this frame even supply valid patches?

coffeecv/infer.py:217

Bean pitch is measured per photo by FFT, not assumed from a fixed zoom level — a user pointing a phone can't be expected to frame consistently. If the frame is too tight to fit even the smallest trained patch size (4 beans across), there's nothing downstream can fix, so it refuses before touching the model.

def scale_verdict(diag, cfg):
    across = diag["beans_across"]
    if across < cfg.patch_beans_min:
        return False, "frame spans only {across:.1f} beans … move the camera back"
    if across < cfg.patch_beans_max:
        return True, f"usable, but {clamp_rate:.0%} of patches clamped"
    return True, "covers the trained range"

The "vote" — 320 probability estimates averaged into one

coffeecv/infer.py:127, 269

Each of the 40 patches gets 8 dihedral views (the rotations/flips training itself augments with), softmax-averaged per patch. Those 40 patch-level averages are then mean-averaged once more into a single vector — every patch and every orientation contributes equally, and the final label is just its argmax.

# inside forward_with_embeddings(), tta=True
acc = probs.copy(); n = 1
for k in range(4):
    for flip in (False, True):
        if k == 0 and not flip: continue
        view = rot90(patches, k); view = flip(view) if flip else view
        acc += softmax(model(view)); n += 1
probs = acc / n                    # n = 8

# back in classify_one(), across all 40 patches
mean = probs.mean(axis=0)          # the final "vote"
ranked = sorted(zip(class_ids, mean), key=lambda t: -t[1])
3

Out-of-distribution guard — the second, independent refusal

coffeecv/infer.py:231, 296

Softmax confidence alone was found to be useless here (0.97 on a genuinely out-of-rig photo, indistinguishable from 0.997 on an in-distribution one) so the guard instead measures how far the photo's embedding sits from every trained class's centroid, in units of that class's own spread. Two bands: warn above the training set's 95th percentile, refuse above the fixed 1.4 threshold.

def ood_scores(embeddings, ref):
    d = norm(embeddings[:, None] - centroids[None]) / spreads
    return d.min(axis=1), nearest_class_ids   # per patch

# classify_one(): median taken over the 40 patches
if warn_at < median <= OOD_THRESHOLD:      # 1.4
    verdict = "warned"                     # still predicts
if median > OOD_THRESHOLD:
    verdict = "REFUSED (out of distribution)"  # no ranked list
