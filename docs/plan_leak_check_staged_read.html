3. P1 — staged read from the index, test first

StatusDone 2026-11-08, e488fab
Blocked byNone

With --staged, leak_check writes the staged set into a temp tree, git diff --cached --name-only -z --diff-filter=ACMR piped into git checkout-index --prefix=<tmp>/ -z --stdin (D1 (c)), and runs the existing scan(tmp, private, files) on it. Findings name the staged path, since scan() and image_findings() work in paths relative to the root they are given. Symlinks and submodules come out as a symlink and an empty directory, which scan() already skips. main takes root=REPO_ROOT, as ruff_staged.main does (D4). ruff_staged's code does not change (D2).

  1. Before any code change: the hook's time on a commit of 30 staged files, in a throwaway git worktree with one comment line added to each of 30 tracked Python files and staged, time .githooks/pre-commit, median of three runs. Kept for P2. Done 2026-11-08: hook 3.38 s; leak_check --staged 0.33 s, ruff_staged 2.96 s, lock_check 0.19 s run alone. ruff_staged with nothing staged: 0.36 s.
  2. The D4 tests in tests/test_leak_check.py, on a temp repo through lc.main([...,"--staged"], root=...) or the function it calls: an email staged then removed on disk is refused; an email added on disk only, to a clean staged file, passes; a staged GPS photo whose disk copy is stripped is refused and named by its staged path (needs exiftool); a staged symlink, submodule and deletion are skipped; a private pattern in a staged path is found; an email staged in a second index, read through GIT_INDEX_FILE, is refused. Each seen failing before the change, for the reason the test names. Done 2026-11-08, e488fab: class StagedRead, 8 tests. The deletion and private-path cases passed the old code too, since neither the file list nor the path check changed; each was seen failing under a mutation instead (--diff-filter with D; the path check removed).
