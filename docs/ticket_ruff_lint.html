Owner request, 2026-10-07. Create a ticket for integrating the Ruff linter into the project, for better Python code. It should also be used in the check script.

1. Summary

Today Ruff is a dev dependency with no configuration and no caller: whoever runs it gets ruff 0.16.10's built-in defaults and 231 findings outside the vendored code, and no check fails on them. After this ticket the rule set, target version and excluded paths are written in pyproject.toml, the code passes it, and .githooks/pre-commit runs ruff check on the staged Python files, and scripts/check.sh runs it on the repo in both tiers, so .githooks/pre-push and scripts/deploy_webapp.sh stop on a finding a commit let through. The work splits into: the configuration (D1, D4), fixing the 62 existing findings (D3), the check.sh step and the pre-commit hook (D5), and the docs that describe the guardrail. The formatter is a later ticket (D2).

2. Background

  • Ruff is already installed. pyproject.toml lists it in the dev dependency group ("ruff: the linter"), uv.lock pins 0.16.10, and the devcontainer's venv has it at /home/vscode/.venv/bin/ruff. Its version moves only through uv lock, as an owner-approved upgrade (ADR 0007). webapp/pyproject.toml does not list it; the release environment does not need it.
  • No configuration. There is no [tool.ruff] table, ruff.toml or user-level config; ruff check --show-settings reports the built-in defaults (line length 88, target 3.12 from requires-python, a broad default rule set).
  • Findings today (ruff 0.16.10, 2026-10-07, defaults):
    • Whole repo: 737, of which 506 are in third_party/efficientvit/, the vendored EfficientViT-SAM (ML-2).
    • Outside third_party/: 231, 121 auto-fixable. By directory: coffeecv/ 120, analysis/ 60, tests/ 36, webapp/ 10, scripts/ 3, models_pretrained/ 2. Largest rules: I001 unsorted imports 43, B023 function uses loop variable 34, RUF100 unused noqa 20, C408 14, PLR0402 12, FURB167 12, PLW1510 subprocess.run without check 11, F401 unused import 11, SIM115 10.
    • With only the pyflakes/pycodestyle core (E4,E7,E9,F): 62, mostly E702/E701 statements on one line, E741 ambiguous names, F401, E402. No undefined names outside third_party/.
    • ruff format --check: 109 of 268 files would be reformatted.
  • Speed. A cold python -m ruff check of the repo outside third_party/ takes about 0.1 s (Ruff itself 0.03 s, the rest a Python start), so it fits the fast tier. In pre-commit, linting each staged file from the index costs about 85 ms per file: about 2.5 s for a 30-file commit (plan P5).
  • Core-set findings by directory (E4,E7,E9,F, the set D1 chose): analysis/ 40, coffeecv/ 16, tests/ 3, models_pretrained/ 2, webapp/ 1. 21 are auto-fixable (F401, E401, F541); the rest (E702/E701 split onto lines, E741 renames, E402, E731) are by hand.
  • The hooks. .githooks/pre-commit runs python -m coffeecv.leak_check --staged (about 1.7 s, most of it the torch import through coffeecv.config) before every commit. .githooks/pre-push runs scripts/check.sh's fast tier before a push to origin, and scripts/deploy_webapp.sh runs --full before a deploy. The pre-commit hook and check.sh are separate: Ruff goes into each (D5).
  • The check script. scripts/check.sh runs leak_check, ticket_check, coverage_report and the unittest suite through its run helper; every step always runs and a failure prints the log's tail. Its header comment and README.md line 26 list the steps, so both name the new one.
  • B023 may be real bugs. Function uses loop variable: a closure defined in a loop sees the variable's last value. The 34 hits are in coffeecv/seg_base_masks.py (8), coffeecv/seg_overlay.py (8), analysis/ml3/printout.py (9), analysis/architecture_screen/bench.py (6) and one each in coffeecv/split_report.py, tests/test_model_and_ood_loading.py and webapp/deploy/render_template.py. Each is read, not auto-fixed.

3. Before and after

Now

  • Ruff installed, unconfigured, run by nobody.
  • 231 findings outside third_party/ under the defaults, 62 under the core set.
  • The rule set is whatever the installed Ruff's defaults are.
  • Neither check.sh nor the pre-commit hook lints; review is the only gate.

After

  • [tool.ruff] in pyproject.toml: select = ["E4", "E7", "E9", "F"], third_party/ excluded, target 3.12.
  • ruff check passes on the repo with the findings fixed, not ignored.
  • The pre-commit hook lints the staged Python files; check.sh lints the repo in both tiers.
  • check.sh's header and README.md list the step.

4. What does not change

  • Ruff's version. Stays at the locked 0.16.10; an upgrade is a separate owner-approved step (ADR 0007).
  • The vendored EfficientViT-SAM. third_party/ is upstream code; it is excluded, not fixed, so it stays diffable against upstream.
  • The webapp's environment. webapp/pyproject.toml and its lock are untouched; check.sh lints webapp/ from the training environment.
  • Behaviour. Lint fixes are refactors: no change to training, inference or what the site returns. A B023 hit that turns out to be a real bug is fixed in its own commit and named in Activity.

5. Risks

IDRiskEvidence and mitigation
R1A fix changes behaviour. Under the core set, 21 fixes are automatic and 41 by hand: splitting a; b lines, renaming l/I/O, moving late imports (E402, where an import may be late on purpose, e.g. after a sys.path edit or a Pillow plugin registration). Apply safe fixes only, keep a late import that is deliberate with a noqa and its reason, and run scripts/check.sh --full before and after each fix commit.
R2A Ruff upgrade changes the rules and fails the check with no code change. The current findings come from 0.16.10's defaults, which change between releases. Select the rule families explicitly in [tool.ruff.lint], so an upgrade does not change which families run. A new stable rule inside a selected prefix (E4, E7, E9, F) does arrive with the upgrade, by the owner's choice (D8); the upgrade itself is an owner-approved uv lock (ADR 0007), and its new findings are fixed in it.
R3Fixes in webapp/ reach the live site. One core-set finding in webapp/. Its fix ships with the next release, after deploy_webapp.sh's full check; keep them in their own commit so a release diff shows them apart.
R4A wide fix commit conflicts with work on the VM. Import sorting and formatting touch many files; the VM's sweep branches are joined by simple merges only (ADR 0009). Land the fixes when the VM has no unmerged commits in the touched files, and merge the VM first.
R5A nested config shadows the root one. Ruff uses the closest pyproject.toml with a [tool.ruff] table. webapp/pyproject.toml has none today, so the root config applies; a test or a comment there keeps it that way.
R6The pre-commit hook lints the working tree, not the commit. ruff check <files> reads files from disk, so a partly staged file is checked with its unstaged edits. Lint the staged blobs instead (git show :<path> | ruff check --stdin-filename <path> -), as leak_check --staged reads the index; check.sh before a push still checks the whole tree.

7. Scope and acceptance

  • [tool.ruff] in pyproject.toml: select = ["E4", "E7", "E9", "F"], third_party/ excluded, each choice commented.
  • ruff check exits 0 on the repo with the 62 findings fixed; a noqa only where the code is deliberate (a late import), with its reason.
  • scripts/check.sh runs a ruff step in both tiers through its run helper; a planted unused import makes the fast tier fail with the finding in the printed tail.
  • .githooks/pre-commit runs Ruff on the staged Python files as staged (R6) beside leak_check; a staged unused import is refused, an unstaged one in the same file is not.
  • scripts/check.sh --full passes before and after the fix commits.
  • check.sh's header comment and README.md's guardrail paragraph name the step; any hook or editor wiring from D5 is in place.

Out of scope

  • ruff format and a ruff format --check step (D2): a later ticket.
  • A type checker (mypy, pyright).
  • Upgrading Ruff past 0.16.10.
  • Changes to third_party/.
  • The checks listed under "Candidates for automated checks" in CODING_STANDARDS.md; Ruff has no rule for either.
