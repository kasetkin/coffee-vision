Ticket OPS-26 · coffee-vision · release environments

Both releases move to Pillow 13.0.0, which fixes 43 advisories; no other package moves

Both hosts' releases run Pillow 12.3.0, which has 43 published advisories (6 critical, 24 high), all fixed in 13.0.0. A visitor's upload reaches the WebP, GIF and BMP decoders and the EXIF parser, on the front and again on the inference host: the reachable advisories exhaust memory or CPU, none of them runs code. This ticket upgrades Pillow alone in all three locks (D1), shows that answers do not move beyond ADR 0020's bars, then deploys. The ticket closes with that deploy. Implemented and tested here on 2026-11-19; the deploy waits for the owner.

1. Summary

Today the front (webproxy-deploy) and the inference host (yappy) run Pillow 12.3.0, and so does training. After this ticket all three run Pillow 13.0.0. Every other package stays at its pin (D1), and imagecodecs could not move anyway (§4). The work splits into four parts:

  1. Raise the pins and re-lock all three projects (coffeecv.lock_check holds them equal).
  2. Prove that canonicalization and answers are unchanged, or changed only within bounds.
  3. Check the native libraries Pillow's wheel bundles, which OSV does not list under the Python package.
  4. Deploy and verify.

2. Background

  • What runs. Read from each host's /opt/coffee-cv/current/.venv on 2026-11-18, and the same as the locks.
    • The front has 6 packages: Pillow 12.3.0, pillow-heif 1.8.0, rawpy 0.27.1, numpy 2.5.3, opencv-python-headless 5.0.0.93 and imagecodecs 2026.10.10.
    • The inference host has 25: the same six, plus Flask, Werkzeug, gunicorn, ai-edge-litert and their dependencies.
    • Both run Python 3.12.14 from uv.
  • Advisories. OSV, queried 2026-11-18, lists 43 distinct advisories for Pillow 12.3.0, all fixed in 13.0.0 (released 2026-10-16). It lists none for any other package in either venv.
  • What a visitor reaches. ADR 0034 limits that to the accepted formats, each opened with its one decoder (coffeecv/data/accepted_formats.csv, canonical.decode, Image.open(..., formats=(plugin,))). JPEG, PNG, AVIF and JPEG XL are decoded by imagecodecs, HEIC by pillow-heif and RAW by rawpy. In Pillow:
    • Header and EXIF parsing for JPEG, PNG and AVIF (_pillow_metadata, and colour_declaration for JPEG). Pillow does not decode their pixels.
    • Full decoding for WebP, GIF and BMP.
    Several advisories rated high are in that reach. All are ways to exhaust memory or CPU:
    • a GIF comment that makes Image.open quadratic;
    • a GIF seek after DecompressionBombError;
    • BMP RLE memory amplification;
    • a PNG eXIf chunk that makes EXIF parsing quadratic;
    • overlapping EXIF IFD tags.
    On the front's 2 vCPU, whose MemAvailable fell to 158 MB during a photo (OPS-15), one such file can stall the site. That keeps Priority High. Outside the reach: the JPEG decoder heap overflow (CVE-2026-112403, GHSA-8g5g-8vmr-9782) needs Pillow to decode a lossless JPEG at reduced scale (draft), and serving never decodes a JPEG with Pillow; the only draft call is training's coffeecv/find_duplicates.py. The worst code-execution advisories are outside it too: FlashPix, EPS through Ghostscript, saving TIFF, PDF. Without ADR 0034 they would be reachable.
  • Three locks, one version. coffeecv.lock_check, run on every commit, refuses a package held at different versions in training's, the web service's and the front's locks (ADR 0033, ML-19 D40 and D41). So this upgrade moves training's Pillow too.
  • Newer releases, none with a listed advisory (PyPI, 2026-11-19).
    • Patch releases: pillow-heif 1.8.1, numpy 2.5.5, markupsafe 3.0.4, click 8.5.1.
    • Larger steps: rawpy 0.28.0, opencv-python-headless 5.1.0.95, gunicorn 27.0.1 (major), ml-dtypes 0.7.0, imagecodecs 2026.11.11.
    None of them moves here (D1). What the research found about each is in Activity, 2026-11-19.
  • Pillow 13 and our code. The 13.0.0 removals (ExifTags.IFD.Makernote, ImageCmsProfile.product_name/product_info, Image._show, GifImagePlugin._save_netpbm, the deprecations scheduled for 13) appear nowhere in coffeecv, webapp, scripts or tests. The nearest call is Image.fromarray(..., mode="P") in tests/test_release_probe.py. pillow-heif, pillow-avif-plugin and pillow-jxl-plugin require pillow with no upper bound, so the lock should resolve with Pillow alone moving.
  • Bundled native code is not in OSV. pillow-heif bundles libheif and libde265. rawpy bundles LibRaw. Pillow bundles libjpeg-turbo, libwebp, libpng and others. OpenCV bundles its codecs. An advisory against one of those C libraries appears under the Python package only when that package publishes one. Pillow did, for libopenjp2 (GHSA-78g4-xqwv-q3g8); the others may not.

3. Before and after

Now

  • Pillow 12.3.0 in all three locks, with 43 open advisories.
  • No record of which native libraries Pillow's wheel ships, at which versions.
  • Nothing tells us when a pinned package gains an advisory. This one was found by an audit done by hand.

After

  • Pillow 13.0.0 in all three locks, deployed to both hosts and verified (--verify).
  • Every other package at its 2026-11-18 pin (D1).
  • The versions of the native libraries Pillow 13.0.0 bundles are recorded in this ticket's Activity, each checked against its own advisories.
  • Advisories are still noticed by hand (D3 out of scope; the owner's later ticket).

4. What does not change

  • imagecodecs 2026.10.10. Under ADR 0033 a change to its version is a change to canonicalization: it needs a re-canonicalization and a retrain, never a routine upgrade. It has no listed advisory. 2026.11.11 also renames the JPEG8 codec that imagecodecs.jpeg8 names. It decodes JPEG, PNG, AVIF and JPEG XL, most uploads, so an advisory against a library it bundles (libjpeg-turbo, libpng, libavif, libjxl) can be fixed only with a re-canonicalization and a retrain.
  • pillow-heif 1.8.0, rawpy 0.27.1, numpy, opencv-python-headless, gunicorn, Flask and the rest of both venvs (D1).
  • The accepted formats and their decoders (ADR 0034). The upgrade changes versions only, not which decoder opens what.
  • ai-edge-litert 2.3.0. It is already the latest release, and a change to it is a new GPU measurement (ADR 0020).
  • The store's canonical photos. Canonicalization processes only new photos (ADR 0037), and §5 R3 checks that the new Pillow would make the same ones.

5. Risks

IDRiskEvidence and mitigation
R1Pillow 13 is a major release and removes deprecated APIs. Its removals were searched for on 2026-11-19 and none is called (§2). Run the full test suite in all three environments, which also shows the AVIF, JPEG XL and HEIF plugins still register.
R2Pixels from WebP, GIF or BMP change, and answers move. Pillow fully decodes only those three. A bundled libwebp change can move WebP pixels. Mitigation: before the deploy, canonicalize the release fixtures and the examples with both versions and compare the bytes. Run deploy_webapp.sh --compare under ADR 0020's bars, and the examples check (OPS-22 D7).
R3The store would canonicalize a WebP, GIF or BMP differently from the photos already in it. Count the store's photos in those formats and re-canonicalize each with Pillow 13. If any differs, the owner decides between re-canonicalizing those photos and accepting the difference (a new D-number).
R4The front's memory. The proxy's MemAvailable fell to 158 MB during a photo (OPS-15). Measure the check service's RSS during the largest fixture photo before and after the upgrade.
R5A bundled C library is still vulnerable after the upgrade. Part 3 records the version of each library Pillow's wheel bundles and checks it against its own project's advisories. One still open is written in Activity for the owner; it does not block this ticket (D1).

7. Scope and acceptance

  • Pillow's pin raised to 13.0.0, and no other. uv lock run for all three projects with uv 0.12.19, and python -m coffeecv.lock_check passes.
  • The full test suite passes in training's environment, and the web service's and front's tests in theirs.
  • The release fixtures and the examples canonicalize to the same bytes as with Pillow 12.3.0, or each difference is listed here with its size.
  • R3: the store's WebP, GIF and BMP photos counted and re-canonicalized with the new version, and any difference brought to the owner.
  • The versions of the native libraries Pillow 13.0.0's wheel bundles (libwebp, libjpeg-turbo, libpng, zlib and the rest) recorded in Activity, each checked against its own advisories.
  • The front's check service RSS during the largest fixture photo, measured before and after (R4).
  • deploy_webapp.sh --compare passes, a full deploy, then --verify passes. Both hosts' venvs show the new versions.
  • OSV, queried again on the deployed venvs, lists no advisory against Pillow. An advisory against any other package is noted in Activity and does not block this ticket.

Out of scope

  • Every package but Pillow (D1), including imagecodecs, ai-edge-litert and the Python interpreter (§4). A newer 3.12 patch release is its own release.
  • D2 and D3, and any follow-up ticket: the owner writes the ticket for checking new versions.
  • The hosts' operating-system packages, which are the owner's root work.
  • Training-only packages (torch and its stack) beyond what lock_check forces to move.
