Owner request, 2026-10-08 (ML-5 D10). If the segmenter fails, or the user disables it in the web app with a checkbox, classify the photo and use the constant 0.5 as the OOD guard. Create an OPS ticket; it will be done later.

1. Summary

The behaviour exists today. After a photo is previewed, a button under it reads "Use full photo instead"; it sends skip_crop=1 with /classify, the whole photo is classified, and the probe scores it like any other photo. This ticket decides whether to keep that button or replace it with a checkbox, and checks the path still holds after ML-5 changes the guard and the segmenter.

2. Background

  • The control. webapp/static/index.html: #crop-toggle-btn, labelled "Use full photo instead" / "Use detected crop", toggles useFullPhoto; the only checkbox on the page is "Show outline" (OPS-6), which only hides the mask outline.
  • The server side. webapp/app.py /classify reads the one bit skip_crop, never a box from the client. infer.segment_bean_region treats it as the ML-2 D18 whole-photo fallback chosen by hand.
  • The guard on that path. infer.classify_one scores every photo with the probe, skip_crop or not, against the threshold in the probe file (0.5 in the shipped probe).

  • The control the owner picks in D1; the probe applies as ML-5's guard ADR says.
